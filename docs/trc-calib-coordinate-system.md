# TRC 与 Calib_board.toml 坐标系说明

## 结论

- `Calib_board.toml` 与三角化内部使用的是同一个世界坐标系。
- `TRC` 不是原样复用 `.toml` 的列顺序；写出前会做一次 `Z-up -> Y-up` 的轴重排。
- 对当前仓库代码，映射关系是：

| `.toml` / 内部世界坐标 | `TRC` 列 |
| --- | --- |
| `world X` | `TRC Z` |
| `world Y` | `TRC X` |
| `world Z` | `TRC Y` |

也就是：

```text
TRC_X = world_Y
TRC_Y = world_Z
TRC_Z = world_X
```

- `Calib_board.toml` 里的“向上”是世界坐标的 `+Z`。
- 因为 `TRC_Y = world_Z`，所以同一个“向上”到了 `TRC` 文件里会落在 `Y` 列。

## 代码依据

这份说明直接对应当前仓库实现：

- `Pose2Sim/triangulation.py` 的 `make_trc()` 在写 `TRC` 前调用 `zup2yup()`。
- `Pose2Sim/common.py` 的 `zup2yup()` 把每个点的三列从 `[X, Y, Z]` 重排成 `[Y, Z, X]`。
- `Pose2Sim/Utilities/reproj_from_trc_calib.py` 在把 `TRC` 重新投影回相机时，又用 `yup2zup()` 变回世界坐标。
- `Pose2Sim/calibration.py` 的外参计算里，`board_position = 'horizontal'` 时棋盘放在 `XY` 平面，`board_position = 'vertical'` 时棋盘放在 `XZ` 平面。
- `Pose2Sim/Demo_SinglePerson/Config.toml` 的注释也提示了 `object_coords_3d` 与 `TRC` 参考系表达不同；但如果注释和直觉冲突，应以 `zup2yup()` / `yup2zup()` 这条真实代码路径为准。

## 问题 1：TRC 与 `.toml` 是否共享坐标系？

严格说：

- 它们共享的是同一个物理世界参考系。
- 它们不共享同一套列名顺序。

换句话说，`TRC` 里的点不是另一个场景，也不是重新标定出来的另一套世界坐标；它只是把 `.toml` / 三角化内部的同一个 3D 点，按 OpenSim 更常用的 `Y-up` 习惯重新排了一次三列。

### 例子 1：同一个 3D 点如何从 `.toml` 变成 `TRC`

假设某个点在 `.toml` / 三角化内部世界坐标里是：

```text
[X, Y, Z] = [0.20, 0.00, 1.50]
```

含义是：

- 沿世界 `X` 方向偏了 `0.20 m`
- 沿世界 `Y` 方向偏了 `0.00 m`
- 高度 `Z = 1.50 m`

写到 `TRC` 后会变成：

```text
[TRC_X, TRC_Y, TRC_Z] = [0.00, 1.50, 0.20]
```

这里最关键的是：

- 原来的“高度” `world_Z = 1.50`
- 会出现在 `TRC_Y = 1.50`

所以如果你在 OpenSim 里看 `TRC`，`Y` 通常就是竖直方向；但在 `.toml` / 标定世界坐标里，竖直方向是 `Z`。

### 例子 2：反向理解 TRC

如果你在某个 `TRC` 里看到一个点：

```text
[TRC_X, TRC_Y, TRC_Z] = [0.30, 1.20, -0.10]
```

那它对应回 `.toml` / 内部世界坐标就是：

```text
[X, Y, Z] = [-0.10, 0.30, 1.20]
```

也就是：

- 世界 `X = -0.10`
- 世界 `Y = 0.30`
- 世界 `Z = 1.20`

## 问题 2：Calib_board.toml 的世界坐标系“向上”是哪根轴？方向是什么？

答案分两层：

### 2.1 哪根轴是“向上”

- 世界坐标里的“向上”是 `Z` 轴。
- 正方向是 `+Z`。

这在棋盘外参建模里很明确：

- `board_position = 'horizontal'` 时，棋盘点在 `XY` 平面上，`z = 0`
- `board_position = 'vertical'` 时，棋盘点在 `XZ` 平面上，`y = 0`

因此无论棋盘水平放还是竖直放，代码里都把“竖直向上”保留给 `+Z`。

### 2.2 “方向是什么”的精确定义

“`+Z` 朝哪边”不是由重力传感器自动推断的，而是由棋盘角点编号顺序决定的。

也就是说：

- 它一定是世界坐标的正 `Z`
- 但它在你实际场地里究竟是“朝天花板”还是“朝地面反方向的反向定义”，取决于你当时那张棋盘在标定时的放置朝向和角点排序

在大多数正常使用场景里：

- 水平放板时，`+Z` 就是离开地面的方向
- 竖直放板时，`+Z` 是沿着板面向上的方向

## `board_position` 的具体含义

### 情况 A：`board_position = 'horizontal'`

这时代码把棋盘放在 `XY` 平面：

```text
board points: [X, Y, 0]
```

含义：

- 棋盘铺在地面或某个水平面上
- 棋盘平面内是 `X` 和 `Y`
- 离开平面的法向是 `+Z`

#### 例子 3：水平棋盘上的一个点

若某个棋盘角点在世界坐标中是：

```text
[X, Y, Z] = [0.18, 0.12, 0.00]
```

则它在 `TRC` 中会写成：

```text
[TRC_X, TRC_Y, TRC_Z] = [0.12, 0.00, 0.18]
```

这说明该点：

- 仍在地面上，因为 `world_Z = 0`
- 所以 `TRC_Y = 0`

### 情况 B：`board_position = 'vertical'`

这时代码把棋盘放在 `XZ` 平面：

```text
board points: [X, 0, Z]
```

含义：

- 棋盘竖起来
- 棋盘平面内是 `X` 和 `Z`
- 棋盘法向是 `Y`
- 沿棋盘向上的方向是 `+Z`

#### 例子 4：竖直棋盘上的一个点

若某个棋盘角点在世界坐标中是：

```text
[X, Y, Z] = [0.18, 0.00, 0.24]
```

则它在 `TRC` 中会写成：

```text
[TRC_X, TRC_Y, TRC_Z] = [0.00, 0.24, 0.18]
```

这时：

- `world_Y = 0`，因为点就在棋盘平面上
- `world_Z = 0.24`，表示它比棋盘原点高 `24 cm`
- 所以 `TRC_Y = 0.24`

## 最容易混淆的点

### 误区 1：`TRC` 的 `Y-up` 就表示 `.toml` 也是 `Y-up`

不是。

当前仓库里：

- `.toml` / 三角化内部世界坐标是 `Z-up`
- `TRC` 输出是 `Y-up`

### 误区 2：竖直放板时，“向上”会变成 `Y`

也不是。

竖直放板时：

- 棋盘法向是 `Y`
- 棋盘向上的方向仍然是 `Z`

### 误区 3：`+X/+Y/+Z` 的正方向完全固定

只有“哪根轴表示竖直”在代码里是固定的；正方向在实际空间里仍取决于棋盘的放置方向和角点顺序。

所以如果你关心“向前”“向左”“向右”到底是哪边，最好用一个你已知方向的参考点做一次验证。

## 实操建议

如果你要快速判断自己的 `Calib_board.toml` 是否符合预期，可以直接检查这三件事：

1. 找一个你确信在地面上的点，看它在世界坐标里是否接近 `Z = 0`。
2. 找一个明显更高的点，看它的世界 `Z` 是否更大。
3. 对照同一时刻的 `TRC`，确认“高度变化”是否落在 `TRC_Y` 上。

## 一句话版本

- `Calib_board.toml` 的世界“向上”是 `+Z`
- `TRC` 里的“向上”是 `+Y`
- 两者描述的是同一个 3D 世界，只是输出列顺序不同
